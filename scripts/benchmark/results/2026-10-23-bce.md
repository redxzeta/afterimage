## Why imports remain missing

The cold diagnostics list the labelled Module endpoints and independently query both `a.id,b.id` and `a.file,b.file` before warm indexing. No labelled endpoints are missing. Both lanes have 36 IMPORTS edges elsewhere in IceCouncil, seven in Nightwire and zero in GigLab; the eight labelled dependencies remain absent by both ID and file. This separates missing relationships from an empty graph or wrong property filter. The synthetic fixture also has both endpoints and returns no edges through either query.

The labels cover seven literal TypeScript/JavaScript import statements and one Nightwire re-export dependency. They deliberately describe source module dependencies, not only syntax named `import_statement`. Source inspection explains distinct implementation limitations:

- [TypeScript relations](https://github.com/redxzeta/afterimage/blob/1a59c728ae3284f0af3b5c781e14a9e2736df6e0/crates/infigraph-languages/languages/typescript/relations.scm#L13) capture the entire quoted string. The [extractor](https://github.com/redxzeta/afterimage/blob/1a59c728ae3284f0af3b5c781e14a9e2736df6e0/crates/infigraph-core/src/extract/relations.rs#L95) carries that text into the target ID, and [import_stem](https://github.com/redxzeta/afterimage/blob/1a59c728ae3284f0af3b5c781e14a9e2736df6e0/crates/infigraph-core/src/graph/store_util.rs#L77) splits it on dots/slashes without stripping quotes or resolving source extensions. Thus quoted `./helpers` yields a trailing quote in the lookup stem, while `./helpers.js`/`.ts` yield an extension/quote suffix. The [bulk writer](https://github.com/redxzeta/afterimage/blob/1a59c728ae3284f0af3b5c781e14a9e2736df6e0/crates/infigraph-core/src/graph/store_bulk.rs#L125) looks up stems of actual files; the [per-file writer](https://github.com/redxzeta/afterimage/blob/1a59c728ae3284f0af3b5c781e14a9e2736df6e0/crates/infigraph-core/src/graph/store_write.rs#L191) instead retains raw extraction targets when matching Module IDs, a separate incremental-storage limitation. These do not match. This is source-supported diagnosis, not a benchmark relabelling.
- The TypeScript relation query has no re-export capture; Nightwire's `export *` dependency is consequently outside that extractor's current coverage. It remains a labelled missing positive.
- Workspace package exports require more than a basename heuristic: the anchored GigLab `@giglab/contracts` export redirects to `src/match.ts`. The import writer does not read that package export map. Quote normalization alone would not establish correct workspace resolution.
- The existing [SCIP importer](https://github.com/redxzeta/afterimage/blob/1a59c728ae3284f0af3b5c781e14a9e2736df6e0/crates/infigraph-core/src/scip/mod.rs#L51) enriches symbols and builds CALLS/INHERITS; it does not materialize Module IMPORTS. A successful SCIP stage therefore does not establish this missing module graph.

The [committed synthetic fixture and exact offline recipe](../fixtures/imports/README.md) separate extensionless, `.js`, `.ts`, re-export and workspace cases. No Rust parser/resolver fix or upstream issue/PR is claimed by this lane.
